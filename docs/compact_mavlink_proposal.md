# 历史规划：yaw与XY期望速度的精简链路

本文件保留先前规划供对照。当前已按飞控74d6a5c适配，实际参数为5Hz yaw、type=0x8001、首字节版本1；运行说明以[当前精简接口](compact_mavlink.md)为准，不能直接照本规划打包。

这是当时的接口规划；制定时旧程序仍使用ID31/250回传和ID84控制。不能只在飞控停发旧消息：电脑桥接、位置环的输入有效性检查、轨迹启动检查和日志都需同步适配。以下帧长度按未签名MAVLink 2、未启用32位目标扩展计算，不含UDP/IP/WiFi/ELRS射频封装。

## 推荐的两类业务数据

保留标准MAVLink外层、来源/目标ID、序号及CRC，改变业务内容。无需先生成新的MAVLink dialect，也不借用手动摇杆轴来伪装物理速度；应验证现有TX/RX/Backpack固件确实完整转发这两种标准消息。

| 方向 | MAVLink | 业务数据 | 频率 | MAVLink帧长 |
|---|---|---|---|---|
| 飞控→电脑 | DEBUG，ID254 | yaw、飞控采样时刻、固定索引 | 20Hz | 21字节 |
| 电脑→飞控 | V2_EXTENSION，ID248 | 两轴速度、使能、最近yaw采样时刻回显、业务长度 | 10Hz | 至多27字节 |
| 双向 | HEARTBEAT，ID0 | 系统识别和诊断 | 各1Hz | 各21字节 |

推荐保留心跳，初期不启用签名、不改变当前网络端口。当前备用链路仍为电脑RX14550、TX10.0.0.1:14555。目标来源及接收目标保持1/1（飞控）、255/190（电脑）。

### 飞控→电脑：ID254 DEBUG

- time_boot_ms：yaw实际测量时的飞控启动毫秒，不能把过期yaw换成新时间继续发送。
- ind：固定1，约定为本项目yaw_rad，电脑同时校验来源1/1。
- value：float，yaw，单位rad，规范化到[-π, π)；无效时NaN。姿态方向约定保持当前机体FRD到参考NED的yaw，与本次start_here航向偏置结合。

只保留本地高度、光流速度、姿态速度内环，相关数据不走这条下行链路。sample_time必须支持识别重启和回绕，飞控重启仍要求重新对齐，不能继承旧目标与偏置。

### 电脑→飞控：ID248 V2_EXTENSION

采用标准外层：target_network=0、target_system=1、target_component=1；message_type=32768作为本地实验协议版本1。后续公开/跨系统协议需按MAVLink扩展类型注册规则分配正式类型。

payload数组249字节先全部置0，仅前10字节有效，按以下顺序逐字段编码为小端；避免直接发送有填充的C结构体：

| 字节偏移 | 类型 | 含义 |
|---|---|---|
| 0 | uint8 | 业务长度，固定10（包括本字节） |
| 1 | uint8 | flags：bit0为控制使能，其余必须为0 |
| 2..3 | int16 | vx_mm_s，前向为正 |
| 4..5 | int16 | vy_mm_s，右向为正 |
| 6..9 | uint32 | yaw_tick_echo_ms，最近一帧可靠yaw的time_boot_ms原值 |

单位为mm/s，分辨率0.001m/s，可编码约±32.767m/s；实际速度上限继续由位置环和飞控各自限制，不能把编码量程当飞行限速。例如0.5m/s编码为500。两个速度同一帧传送，避免X/Y分包造成样本不配对。Z、期望yaw和角速度不传，由飞控原有逻辑负责。

ID248本身有5字节固定字段，业务数据至多10字节，加MAVLink 2外层12字节，最大27字节。MAVLink 2会裁掉末尾的零字节；业务长度字段用来恢复被裁掉的零，不能强制要求线上的消息长度等于完整249字节数组长度。**必须使用MAVLink 2**：MAVLink 1不会做该裁剪，会把ID248发成大包，失去精简意义。

## 防止排队的旧命令仍被执行

保留300ms未收到有效新指令的超时保护；同时引入以下来源时间检查。仅检查本地接收超时不够：即使指令排队4秒后才到，接收时刻仍是“新”的。

飞控用自身时钟检查：

```c
uint32_t age_ms = (uint32_t)(HAL_GetTick() - yaw_tick_echo_ms);
```

地面验证可先以500ms为端到端时效上限；最终根据实测抖动和控制要求设定。该age包含yaw采样、下行、电脑等待和上行时间，是保守的总年龄上界，**不是单向上行延迟**。它使用飞控自己的时间，无需直接比较电脑时钟与飞控时钟。

- 电脑必须回显实际收到的yaw时刻，不能自行递增或改写成预计飞控当前时刻。
- 使能为0时立即归零，不能因为时间检查失败而忽略停止请求。
- 使能为1但来源、目标、长度、数值、速度限制或时效检查不通过时，不采用非零目标，也不续期。过期命令不能继续维持之前的非零目标；零目标与遥控接管按已约定仲裁执行。
- 只有新的、通过全部检查的指令可刷新目标与接收超时。迟到、重复消息不续期。
- yaw失效/过期时电脑停止产生有效位置控制；地面直接速度测试也应采用明确的独立测试模式，不通过伪造采样时间绕过这套检查。

这能让已经到达飞控的4秒旧指令被拒绝，但不会修复导致延迟的无线重传、排队或飞控阻塞。

## 带宽估算

按上表频率，yaw 21×20=420B/s，速度最多27×10=270B/s，双向心跳合计42B/s，总计约732B/s的MAVLink字节流。当前ID31和250各20Hz、ID84为10Hz、飞控心跳2Hz和电脑心跳1Hz，按常见完整帧估算约2433B/s；精简后约减少70%。射频调度、确认和重传还会产生开销，不能将这些数直接等同于有效空中吞吐。

已用本项目固定版本C头文件做本地编码/解析探针：速度最坏情况27字节，尾零数据19字节，CRC及249字节数组补零后内容一致；DEBUG yaw为21字节。尚未完成该协议的ELRS端到端和飞控联调。

## 电脑和实验功能需同步调整

- 位置环：保留UWB、航向对齐、map到机体水平速度旋转、限速/限加速度、定点/航点及水平轨迹。采用纯P位置环（当前D本来为0）；不得伪造实测速度为0来通过原检查。
- 位置选择：光流里程计只观察的旧功能也失去速度来源，应在精简模式明确停用/标记无数据；正常位置只用滤波UWB。
- 到达判断/轨迹：不再要求ID250新鲜或实测速度小于门限。可基于UWB位置误差和驻留时间判定；若以后用UWB差分估速，需单独滤波评估，不等同于原光流实测速度。
- 日志：保留期望/实际位置、期望速度和yaw；实测速度、roll/pitch、三轴角速度标记未记录，不能用0代替。论文的光流补偿对照实验需切回完整遥测模式或从飞控本地日志导出。
- 部署：作为独立compact配置保留旧链路，电脑/飞控两端先在地面切换一致，再验证协议、时间检查、停止和重启行为。
